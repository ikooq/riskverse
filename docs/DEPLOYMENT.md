# RISKVERSE — публикация и локальный сервер

## Vercel Hobby

В корне есть `vercel.json` и две Node.js Functions: `api/health.ts`, `api/analyze.ts`. Vercel собирает Vite frontend в `dist` и обслуживает API на том же домене. Постоянно запущенный ноутбук не нужен. Команда `npm start` на Vercel не используется.

Импортируйте GitHub-репозиторий, оставьте framework Vite и настройки из `vercel.json`. Серверные переменные проекта: `GEMINI_API_KEY` (Secret / Sensitive, Production и Preview), `GEMINI_MODEL=gemini-3.1-flash-lite`, `RISKVERSE_REQUESTS_PER_MINUTE=5`, `RISKVERSE_DAILY_ANALYSES=30`. Не задавайте публичный префикс `VITE_` для ключа. `PUBLIC_ORIGIN`, `HOST` и `PORT` для Functions не нужны. Не включайте платный тариф, платные интеграции или оплату Gemini для этого демонстрационного размещения.

Функция ограничена 60 секундами. Клиент уменьшает длинную сторону снимка до 2048 px и при необходимости дополнительно сжимает, проверяя размер **всего JSON до 4 000 000 байт**. Это оставляет запас под лимит тела Vercel 4.5 MB. Пользователь может выбрать исходный JPG/PNG/WebP до 8 МБ.

В Production используется бесплатная база Upstash Redis `riskverse-limits`, подключённая через Vercel Marketplace. Переменные `KV_REST_API_URL` и `KV_REST_API_TOKEN` серверные; поддерживаются также `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN`. По умолчанию разрешены 30 попыток AI в сутки UTC на весь сайт и 5 POST-запросов в минуту на клиента. Lua-команды атомарно проверяют и увеличивают счётчики на Redis primary; холодный старт и новые деплои счётчик не обнуляют. Production и Preview разделены пространствами ключей. Вместо IP в краткоживущем ключе хранится хеш; фотографии, ответы AI и пользовательские аудиты в Redis не записываются.

Дневная попытка резервируется только после проверки изображения, непосредственно перед запросом провайдеру. Неуспешный ответ AI тоже расходует попытку. При недоступной или отсутствующей базе в Production новые анализы получают 503, провайдер не вызывается. `/api/health` показывает `limits.mode=shared`, `process` или `unavailable`; это наличие конфигурации, не проверка доступности Redis или квоты Gemini. Локальная разработка без Redis сохраняет ограничение одного процесса; его сброс при перезапуске допустим только для локального показа. Аудиты остаются в браузере.

Проверка новых фото после публикации (три согласованных публичных файла скачиваются из Wikimedia при первом запуске; источники и лицензии в `NEW_PHOTO_CASES.json`):

```powershell
$env:RISKVERSE_API_URL='https://ваш-проект.vercel.app'
npx --no-install tsx scripts/evaluate-deployment.ts
```

Результаты и фото сохраняются в игнорируемой `output/ai-evaluation`; они не попадают в коммит автоматически. Скрипт делает реальные запросы и расходует квоту бесплатного тарифа. Референсы видимого содержания записаны до анализа; экспертной оценки точности они не заменяют.

## Обычный Node.js хостинг

`npm start` запускает frontend из `dist` и серверные `/api/health`, `/api/analyze` на одном адресе. Для запуска больше не нужен Vite или отдельный прокси к локальному API. Нужен Node.js 22.22+.

## Локальный показ собранной версии

```powershell
npm ci
npm run build
npm start
```

Адрес по умолчанию: http://127.0.0.1:8787. Терминал должен оставаться открытым. Существующий `.env.local` загружается только сервером; ключ не нужен при сборке. На новом компьютере скопируйте `.env.example` в `.env.local` и заполните `GEMINI_API_KEY`. Учебная модель и ручная разметка работают без API-ключа.

`npm run dev` остаётся командой для разработки. `npm run preview` показывает только статическую сборку. `npm run api` — прежний вспомогательный локальный API; для готового сайта используйте `npm start`.

## Настройки хостинга

В настройках Node-хостинга укажите:

- Install: `npm ci`
- Build: `npm run build`
- Start: `npm start`
- `HOST=0.0.0.0`
- `PORT`: порт, назначенный хостингом; локальное значение по умолчанию — 8787.
- `PUBLIC_ORIGIN=https://ваш-домен`: точный публичный origin без пути. Прокси должен сохранять исходный HTTP `Host`. Сервер не доверяет произвольному `X-Forwarded-Host`.
- `GEMINI_API_KEY` и при необходимости `GEMINI_MODEL`: только серверные переменные окружения хостинга.

TLS/HTTPS завершает прокси хостинга. Браузер отправляет фото на `/api/analyze` того же сайта, а сервер обращается к Gemini. Запущенный ноутбук автора после размещения на хостинге не требуется. Готовый `dist-server` запускается обычным Node.js, без `tsx`, Vite и dev-зависимостей.

Проверки процесса: `/healthz` и `/readyz` возвращают HTTP 200 после успешного запуска с найденной сборкой. `/api/health` показывает наличие конфигурации провайдера, но не проверяет квоту и не делает платный запрос.

## Ограничения запросов

| Переменная | По умолчанию | Что ограничивает |
|---|---:|---|
| `RISKVERSE_REQUESTS_PER_MINUTE` | 5 | POST-запросы анализа с одного сетевого адреса за 60 секунд |
| `RISKVERSE_DAILY_ANALYSES` | 100 | Попытки обращения к AI-провайдеру за сутки UTC; `0` отключает новые анализы |

Одновременно выполняется один анализ; лишние запросы получают HTTP 429 и `Retry-After`. Дневной счётчик увеличивается только при обращении к провайдеру, включая неуспешный ответ провайдера. Некорректные фото не расходуют его. Сырые фото и ключи сервер не записывает в журналы или базу данных.

Счётчики живут в памяти одного процесса и сбрасываются при перезапуске. За прокси без доверенного определения IP пользователи могут делить один лимит. Эта конфигурация предназначена для одного демонстрационного экземпляра: при нескольких экземплярах нужны общий счётчик и согласованная обработка IP на инфраструктуре. Лимиты запросов не заменяют лимит расходов в кабинете AI-провайдера.

## Контейнер

Подготовлены `Dockerfile` и строгий `.dockerignore`: локальные ключи, история Git, аудиты и прежние релизы не входят в контекст сборки.

```powershell
docker build -t riskverse .
docker run --rm -p 8787:8787 --env-file .env.local -e HOST=0.0.0.0 riskverse
```

На хостинге передайте серверные переменные через его защищённые настройки. Контейнер запускается от пользователя `node`. Сборка контейнера зависит от доступности Docker и реестра образов; сам Docker-образ в этой проверке не запускался.

## Проверка перед публикацией

Откройте сайт с другого устройства, создайте аудит из согласованного фото, выполните один AI-анализ и скачайте отчёт. Проверьте восстановление аудита после перезагрузки. Данные остаются локально в браузере конкретного устройства; аккаунтов и синхронизации между устройствами в этой версии нет. Перенос выполняется через «Скачать аудит целиком» / «Открыть аудит».

Фактический адрес публикации и результаты живой проверки фиксируются отдельно после успешного размещения. Наличие этих файлов само по себе не подтверждает публикацию.
